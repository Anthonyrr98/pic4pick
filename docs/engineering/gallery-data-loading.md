# 网页作品列表加载与缓存

首页启动时立即请求公开作品列表，与 React 初始化和图库代码加载并行。
这条请求直接使用 Supabase 公开 key，沿用匿名 RLS，只读取已审核且未隐藏的作品。
不经过管理后端，也不等待登录会话。审核拒绝原因不在公开请求字段中。

作品信息缓存使用独立键 `pic4pick_public_photos_v1`，不复用本地管理模式的
`camarts_approved_photos`。缓存包含数据源、版本、获取时间和公开作品记录，
不缓存照片文件、认证 token 或 API key。

- 5 分钟内的缓存可以立即显示，同时后台请求最新列表。
- 同一次页面访问中，并发请求共用一个 Promise；一分钟内复用刚获取的结果。
- 页面重新变为可见或保持可见满一分钟时检查更新；隐藏标签页不定时请求。
- 请求总时限为 15 秒；只有数据库 statement timeout 才尝试取消排序后重读，仍受同一个时限约束。
- 刷新失败时保留未过期缓存并显示错误；过期、损坏或来自另一项目的缓存不用于初始化。
- 新列表完整替换旧列表，包括作品被隐藏、删除或公开列表变空的情况。
- 管理端作品写操作成功后清除该浏览器缓存，并通知同源其他标签页刷新；旧的未完成请求不能覆盖此次失效操作。
- 不同访客之间不共享浏览器缓存。没有有效缓存的首次访问仍受 Supabase 网络响应时间影响；提前请求减少的是页面代码加载形成的串行等待。

验证：先运行 `npm run dev`，再运行 `npm run test:gallery-cache`。
测试包含 10 秒慢请求、后台替换、刷新失败、到期失效和管理端跨标签页失效。
